# One gate reads one report

Every analysis, Gradle task or CLI run, reads exactly one JaCoCo XML file. The tool never merges reports. Combining coverage across test suites or modules is JaCoCo's job, done correctly at the execution-data level (`jacoco-report-aggregation`, or a `JacocoReport` task fed multiple execution-data files), and the gate then reads the merged XML like any other. We considered accepting multiple XML files with a per-method collision rule (best coverage wins), but any XML-level merge is an approximation by construction, the true union of branch coverage is not recoverable from two reports. Rejecting the approximation keeps the core free of merge semantics and keeps the numbers honest. The cost, users who want one combined gate must wire the JaCoCo aggregation themselves, the plugin does not crawl subprojects. Decided in crap-diy.5, details in research/gradle-plugin-spec.md.
