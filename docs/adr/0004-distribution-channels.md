# Distribution channels per artifact

Each artifact ships on the channel its consumer's resolver reads, and the CLI has no resolver. `crap4j-core` publishes to Maven Central. `crap4j-gradle-plugin` publishes to the Gradle Plugin Portal and dual-publishes, marker POM included, to Maven Central, because the first consumer is an enterprise whose peers often allowlist `mavenCentral()` but not `plugins.gradle.org`. `crap4j-cli` is an application, not a dependency, so the fat jar attaches to GitHub Releases and never goes to Central, following Checkstyle, google-java-format, ktlint, and detekt (JaCoCo's `nodeps`-classifier CLI on Central is the anti-example). Published releases are immutable on every channel, so this split is expensive to walk back. Details in research/publishing-spec.md.
